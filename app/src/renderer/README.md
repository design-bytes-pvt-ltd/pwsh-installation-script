# Renderer (UI)

The Electron renderer: a React app bundled by Vite (`vite.config.ts` uses this folder as its root).
It talks to the main process only through `window.installerApi` (see `src/shared/api.ts` and
`src/main/preload.ts`).

> Migration status: the UI still runs from the original vanilla `main.ts` / `index.html` /
> `styles.css`. The folders below are the target layout; screens move into them one at a time.

## Layout

```
renderer/
├── index.html      Vite entry. Holds the Content-Security-Policy.
├── main.tsx        Mounts <App/> (replaces main.ts once the screens are ported).
├── app/            App shell: App.tsx, providers (store, error boundary), routing, global error hooks.
├── pages/          One folder per page. Composes features + layout; little logic of its own.
├── features/       Domain code grouped by feature: components/, hooks/, logic, __tests__/.
│   ├── system/     Hardware / installed-tools probe.
│   ├── models/     Model table, selection, download-size summary.
│   └── install/    Install options, step progress, logs, failures.
├── components/
│   ├── ui/         shadcn/ui components (button.tsx, card.tsx...). Generated by the CLI, then owned by us.
│   └── layout/     Page chrome (Header, StepIndicator, PageContainer).
├── hooks/          Generic hooks shared across features (shadcn also puts its hooks here).
├── services/       The only code that calls window.installerApi.
├── store/          App-wide state (React Context + useReducer).
├── lib/            Pure helpers (formatting; utils.ts re-exports `cn`). No React, no DOM.
├── styles/         globals.css: Tailwind entry + theme variables (light and .dark). Only global CSS lives here.
├── assets/         icons/, images/, fonts/ imported from code so Vite fingerprints them.
└── types/          Ambient declarations (global.d.ts for Window.installerApi, etc.).
```

App icons for the installer itself belong in `app/build/`, not `assets/`.

## UI kit: shadcn/ui

- Config is `app/components.json` (Radix base, `nova` preset, lucide icons, CSS variables).
  The `@/` import alias points at this folder.
- Add components from `app/`: `npm run ui:add -- dialog select`. The script sets
  `TS_NODE_PROJECT=tsconfig.renderer.json` because the root `tsconfig.json` is the main-process
  config, and the CLI needs the renderer's `@/` alias. It also removes `npm_config_allow_scripts`:
  `npm run` exports a user-level `allow-scripts` setting to child processes, and the `npm install`
  that shadcn runs for new packages then fails with `EALLOWSCRIPTS`. It uses POSIX `env`, so on
  Windows run it from Git Bash or WSL.
- **Dependencies go in `devDependencies`.** Vite bundles everything the UI imports, so nothing
  renderer-only belongs in `dependencies` (electron-builder would ship a second copy in
  `node_modules`). If `ui:add` installs a package into `dependencies`, move it with `npm install -D <pkg>`.
- Edit the generated files freely; they are our code now. Re-running `ui:add` for an existing
  component asks before overwriting.
- shadcnspace and other shadcn-compatible blocks go into `features/` or `pages/` and should build
  on the components in `components/ui/`.
- Theme: change the CSS variables in `styles/globals.css` (`:root` = light, `.dark` = dark). The
  app is dark-themed, so the root element gets `class="dark"` once the React UI is live.

## Rules

**Imports flow one way**

```
pages → features → components → lib
            ↓
     store / services → window.installerApi
```

- `components/` is pure, prop-driven UI. It never imports from `features/`, `store/` or `services/`.
- A feature may use another feature's public `index.ts` only, never its internals.
- IPC types come from `../shared`. Never redeclare them here.

**Styling**

- Tailwind utility classes in JSX. Combine conditional classes with `cn()` from `@/lib/utils`.
- Use theme colors (`bg-card`, `text-muted-foreground`, `border-border`, `bg-destructive`) rather than
  raw palette colors (`bg-slate-800`) or hex values. A redesign should mostly touch
  `styles/globals.css` and `components/ui/`, not pages.
- Variants of a component go through `cva` (see `components/ui/button.tsx`), not ad-hoc class strings.

**File naming**

- `components/ui/`: lowercase files, one per component (`button.tsx`), as shadcn generates them.
- Our own components: PascalCase files (`ModelTable.tsx`), optionally in a folder with an `index.ts`
  and `__tests__/` when they grow.
- Page folders use PascalCase; feature and other folders use lowercase.

**Tests**

- Put tests in `__tests__/` next to the code (`*.test.ts` or `*.test.tsx`), the same as `src/main`.
- A test that needs a DOM starts with `// @vitest-environment jsdom` and uses `@testing-library/react`.

**Routing and state**

- The installer is a linear wizard, so `app/` switches pages from state. When pages stop being
  linear, add `react-router` with `HashRouter`, because the app is loaded from `file://`.
- Start with Context + `useReducer` in `store/`. Reach for a library only if that gets unwieldy.

**Security**

- Never use `dangerouslySetInnerHTML`. Render text as text.
- Keep the CSP in `index.html` strict. The production build works with `script-src 'self'`,
  `style-src 'self'` and `font-src 'self'` (fonts are bundled, nothing loads from the network).
- Overlay components that lock scrolling (Dialog, Sheet, Drawer) inject a small `<style>` tag.
  When you add one, check DevTools for CSP errors. If it is blocked, allow inline styles only
  (`style-src 'self' 'unsafe-inline'`), never inline scripts.
